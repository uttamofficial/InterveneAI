# Synthetic Intervention Layer — Documentation

> **The Olist dataset does NOT contain a real randomized coupon/intervention
> experiment.** There is no observed treatment, no control group, and no
> intervention outcome in the real data. Everything described below as
> simulated is synthetic. No number in the synthetic layer is a discovered
> real-world effect.

## What is observed real data

From `data/processed/customer_features_v3.parquet`, used **only** as
simulation inputs:

- `customer_unique_id`, `snapshot_date` — panel identifiers.
- `recency_days`, `purchase_count_180d`, `purchase_count_30d` — covariates
  that shape simulated assignment and outcomes.

The real target `purchased_next_60_days` is **never** copied into the
synthetic dataset (asserted absent by validation).

## What is simulated

`data/synthetic/intervention_experiment.parquet` (348,767 rows, one per
real panel row), generated by `src/causal/simulate_experiment.py`:

| Column | Meaning |
|---|---|
| `treatment` | 1 if any intervention, else 0 |
| `intervention_type` | 0 = none, 1 = coupon, 2 = free_delivery, 3 = loyalty_points |
| `intervention_cost` | Assumed BRL cost (0 / 5 / 8 / 3) |
| `outcome` | Simulated binary purchase (seeded Bernoulli) |
| `true_propensity` | Oracle P(received arm) — validation only, never a feature |
| `true_cate` | Oracle effect of received intervention vs control (0 for controls) |

`data/synthetic/intervention_params.json` records mechanism, arm
probabilities, seed, assumed effects/costs, and a synthetic-data warning.

## Why simulation is necessary

Causal questions ("what would this intervention do?") cannot be answered
from Olist alone: treatment was never randomized or even recorded, so any
"effect" estimated on real data would be pure confounding. A simulation with
**known ground truth** lets later phases develop and benchmark causal
estimators (comparing estimates against `true_cate`) before anyone trusts
them on observational data.

## Data-generating process (assumptions, not findings)

- Base: `0.004 + 0.004·(1 − recency/180) + 0.004·I(count_180d ≥ 2)`,
  calibrated so the control rate (~0.62%) sits near the observed ~0.60%.
- Assumed absolute effects: coupon **+0.8pp**, free_delivery **+0.5pp**,
  loyalty_points **+0.3pp**; 50% larger for recently active customers
  (`count_30d > 0`). Outcome is a seeded Bernoulli draw.
- Assignment: `random` (default 0.4/0.2/0.2/0.2, configurable via
  `--arm-probs`) or `targeted` (treatment probability rises with recency —
  confounded **by design**, since recency also drives outcomes).
- Default run: `--mechanism random --seed 42`. Observed simulated rates:
  control 0.62%, coupon 1.56%, free_delivery 1.14%, loyalty 0.98% —
  ordered as assumed, by construction.

## Assumptions

1. Effect sizes, heterogeneity shape, costs, and base rate are author
   choices, not estimates. 2. Bernoulli outcomes conditional on the stated
   probabilities (no interference/spillover between customers — SUTVA
   assumed). 3. Under `random`, assignment is ignorable by construction;
   under `targeted`, recency confounds and must be adjusted for.
4. Oracle columns are method-validation tools, not model inputs.

## Limitations

- Synthetic effects carry **zero information** about real Olist customers'
  response to coupons or delivery offers; do not report them as findings.
- The DGP is deliberately simple (additive, few interactions); estimators
  that work here may still fail on real-world complexity.
- Costs are flat per intervention (no customer-level variation, no budget
  dynamics). No interference, no carryover across snapshots, no
  non-compliance modeled.
- Only the default `random`/seed-42 dataset is saved; other configurations
  are reproducible on demand via CLI flags.

## Validation performed (in-script, all passing)

Treatment counts/proportions (match configured probabilities within 1pp
under `random`), outcome rates overall and per arm (treated > control for
all assumed-positive effects), exact cost mapping, binary complete outcomes,
real-target absence, and reproducibility (same seed → identical frame;
different seed → different assignment). No causal estimation is implemented
in this phase.
